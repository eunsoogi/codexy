When implementation is classified as child-owned, the owning child MUST
establish its branch/worktree before implementation evidence is accepted.
Read-only requests and current-task-owned implementation MUST NOT require a
child task or child-owned branch/worktree; their applicable host and
GitHub/Devtools contracts remain in force. An issue, GitHub assignee, or
publication MUST NOT by itself establish child ownership or authorize a new
task. A child-owned implementation handoff MUST list current
PR/threads/head/local+remote/labels/project. Only installed applicable
GitHub/Devtools contracts apply; absence MUST fail closed; private/missing proof
MUST NOT substitute.
