# TDD classification policy

Engineering boundaries require engineering-level tests: production code,
runtime behavior, validators, parsers, hooks, CLIs, workflows, installers,
package resolution, tool behavior, defect repairs, behavior-preserving
refactors, and executable contracts.

Documentation, instruction-only skills, prompts, declarative metadata,
roadmaps, inventories, diagrams, examples, and copy edits use proportional
proof. Mixed requests retain the engineering duty for their engineering
boundaries.

The executable boundary sets are maintained by the packaged runtime validator.
