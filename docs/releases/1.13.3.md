# Codexy 1.13.3 release notes

Codexy 1.13.3 narrows the normal Watcher wait response and avoids follow-up
reads when the current observation already contains enough evidence. This keeps
the existing single `watcher_wait` contract; it does not add a compact/full
response mode or another wait tool.

## Watcher response changes

The normal `watcher_wait` result keeps `status`, top-level `sessionId`,
`nextCursor`, `events`, and `health`. The `health` object now contains only
`status`, `watcherState`, `lastObservationAtMs`, and `lastError`. The following
fields are no longer repeated inside `health`: `actor`, `sessionId`,
`assignmentId`, `parent`, `watcher`, `targets`, `generation`, `queueDepth`,
`lastMaterialEventAtMs`, `waiting`, `transport`, `transportConnected`,
`nativeStatus`, and `expiresAtMs`. The top-level `sessionId` remains. Use
`watcher_health` when a concrete diagnostic needs the detailed identity, target,
queue, or transport state.

Each event in `events` now contains exactly `eventId`, `sequence`, `kind`,
`target`, `summary`, `observedAtMs`, and `evidence`. The public event no longer
includes `fingerprint`; the value remains in durable event records for retry and
explicit-ID conflict validation. Existing stored events replay without a schema
migration, and `eventId` remains the public event identity.

## Caller migration

- Event consumers must use `eventId` and the seven-field event shape rather than
  reading `fingerprint` from wait results.
- Call `watcher_health` only when detailed health is needed for a specific
  unresolved diagnostic. Do not issue it automatically after every wait.
- A returned JSON result with `status=cancelled` includes
  `cancellationReason=request_cancelled` for request-binding interruption or
  `cancellationReason=session_cancelled` for durable `watcher_cancel`. A
  same-connection MCP cancellation may suppress the JSON result entirely.

The in-repository callers and packaged Watcher guidance were migrated. External
consumers were not comprehensively inventoried, so this note does not assert
that every external caller is compatible. Consumers that depend on removed
fields must migrate before updating.

## Observation guidance and verification limits

The Watcher can skip a bounded follow-up read when a current `wait_threads`
result already provides sufficient, exact target and turn evidence. It keeps the
read when results are missing, truncated, contradictory, or unbound, and
preserves the distinct queued health-event path. The changes and their evidence
are recorded in
[Watcher correctness and contention stress](../watcher-test-coverage.md) and in
[#1306](https://github.com/eunsoogi/codexy/pull/1311),
[#1307](https://github.com/eunsoogi/codexy/pull/1313),
[#1312](https://github.com/eunsoogi/codexy/pull/1314), and
[#1308](https://github.com/eunsoogi/codexy/pull/1315).

The published response-size measurements count serialized UTF-8 bytes; they do
not measure tokenizer use, model consumption, or billing. The bounded
observation for #1308 used the installed Codexy 1.13.2 Watcher with candidate
instructions, so it is evidence about those instructions, not an installed
1.13.3 package. Host observations are limited to the documented supported route;
hidden inference and other hosts remain unverified. The observed host
cancellation overlapped a child terminal message, so its sole cause was not
established. No total token or cost savings are claimed, and the separate #1309
cost campaign is not part of this release.
